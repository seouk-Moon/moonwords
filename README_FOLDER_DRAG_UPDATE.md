# 폴더 안에 폴더 · 끌어서 이동 · 길게 누르기 메뉴

이전 수정을 반영한 GitHub main c47d797 기준 변경 파일입니다.

## 이번 변경
- 메인 보관함에서 폴더를 다른 폴더에 끌어 넣을 수 있습니다.
- 본문과 통합단어장 카드를 표시된 폴더에 끌어 넣을 수 있습니다.
- 폴더 경로의 상위 폴더에도 놓을 수 있습니다. '내 보관함'이나 '미분류 · 최상위로 이동'에 놓으면 폴더는 최상위, 문서는 미분류로 갑니다.
- 모바일은 폴더/자료를 약 0.55초 꾹 누르면 이름 변경·이동 메뉴가 열립니다. PC에서는 우클릭, 모든 기기에서 ⋯ 버튼도 가능합니다. 모바일에서 스크롤을 시작하면 길게 누르기는 취소됩니다. PC는 드래그로, 모바일은 길게 누르기 → 이동으로 정리할 수 있습니다.
- 폴더를 열면 하위 폴더와 해당 폴더에 직접 들어 있는 자료를 볼 수 있습니다. 경로 버튼으로 상위 폴더로 돌아갈 수 있습니다. 전체 자료는 기존처럼 모든 자료를 보여줍니다.
- 현재 폴더 안에서 '새 폴더'를 만들면 그 안에 생성됩니다. 최상위에서 만들면 최상위에 생성됩니다.
- 이동 대상 목록에는 전체 폴더 경로를 표시하며, 자기 자신/하위 폴더는 대상에서 제외합니다. 서버에서도 순환·다른 사용자의 폴더로의 이동을 거부합니다.
- 폴더 삭제는 그 안의 자료를 미분류로, 직속 하위 폴더를 최상위로 옮깁니다. 자료나 하위 폴더의 내용은 삭제하지 않습니다. 삭제 확인창에서 이를 안내합니다.
- 이름/이동 저장 실패 시 원래 화면 상태를 유지하고 오류를 표시합니다.

## 네가 할 일 (한 번만)
1. ZIP을 풉니다.
2. Supabase → SQL Editor → New query에서 `supabase/migrations/202610220001_nested_folders.sql` 전체를 붙여넣고 Run합니다. 기존 폴더와 문서를 삭제/이동하지 않는 구조 추가입니다. 반복 실행도 가능합니다.
3. ZIP의 파일을 기존 moonwords 저장소의 같은 경로에 추가/덮어쓰고 GitHub에 Commit/Push합니다. 기존 저장소를 통째로 지우지 마세요.
4. GitHub Pages 배포가 끝나면 새로고침합니다. PC는 Ctrl+Shift+R입니다.
5. PC에서는 폴더/자료를 폴더 위에 놓아 보고, 모바일에서는 꾹 누르기 또는 ⋯ → 이동을 사용합니다.

이번 수정에는 Edge Function 재배포나 새 API 키가 필요 없습니다.

## 검증
- Pages 프로덕션 빌드 통과. 기존 mammoth 타입 선언 등 저장소 전체 tsc 오류는 별도 기존 문제이며, 변경한 src 파일에서는 새 오류가 없었습니다.
- PostgreSQL 호환 엔진에서 실제 migration 두 번 실행, 중첩 저장, 자기/하위/타인 폴더 이동 거부, 최상위 복귀, 폴더 삭제 시 자료 보존 검증.
- Chromium + Supabase 응답 모의 서버에서 실제 폴더·문서 드래그, 길게 누르기, 이름 변경, 이동 목록, 실패 시 유지, 새로고침 후 재로딩, 모바일 360/390/768px 검증.
- 운영 Supabase/사이트에 직접 배포하지 않았습니다.
