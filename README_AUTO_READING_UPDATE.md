# MoonWords 촬영 즉시 생성 · 원본 문제 보존 · 생성 중 복습

기준: 사용자가 이전 변경을 적용 완료한 GitHub main 74f929c. 이 파일 묶음은 그 이후의 새 변경입니다. 기존 달 성장, 로그인, 세트·단어장·통합단어장, 모바일 UI와 Printmaker 연결은 유지합니다. Printmaker 저장소 변경은 없습니다.

## 이번 수정
- 첫 화면과 업로드 화면의 ‘사진으로 추가’를 ‘본문 추가’로 변경했습니다.
- 촬영/앨범 사진을 고르면 한국어+영어 OCR → 사진과 텍스트 AI 분석 → 저장까지 바로 진행합니다. 인식 결과를 고친 다음 만들기를 눌러야 했던 단계와 사진의 필수 빈칸 확인 단계를 없앴습니다. 생성 실패 후에는 사진 영역을 조절해 다시 시도할 수 있습니다. 기존 파일/텍스트의 빈칸 확인 기능은 유지합니다.
- 사진은 한 문제의 지문·한글 질문·모든 보기가 함께 나오도록 찍으세요. 최초 영어·한국어 인식 데이터 다운로드에는 인터넷이 필요합니다. 사진은 기기에서 크기를 줄이고, 기존 분석 요청에 사진과 텍스트를 함께 보내 읽도록 했습니다. 별도의 사진 원본 파일은 저장하지 않습니다.
- 원본 문제를 새로 생성한 학습용 문제와 분리해서 저장·표시합니다. 원래 보기 ①~⑤가 있으면 5개 모두 기록하도록 요청하며, 학습용 4지선다로 줄이거나 덮어쓰지 않습니다. 원본 질문·보기·번호·빈칸·(A)(B)(C) 등은 원문 순서를 보존하고, 순서나 빈칸의 정답을 임의로 채우지 않도록 분석 지침을 바꿨습니다.
- 원본 전사와 최초 OCR 텍스트를 모두 보존합니다. 파일·붙여넣기 원문은 AI가 다시 쓴 텍스트로 바꾸지 않습니다. 공부 화면 상단의 ‘원본 문제와 보기’, ‘인식한 원문 전체 보기’에서 확인할 수 있습니다.
- 목적·심경·주장·함축 의미·요지·주제·제목·도표·일치/불일치·어법·어휘·빈칸·순서·삽입·무관 문장·요약·장문 등 원본 문제 유형을 분류해서 표시합니다.
- 촬영 본문과 모의고사 지문은 한 구간으로 묶습니다. 영어 문장별 해석·듣기·수정 기능은 유지합니다. 기존에 저장한 문장의 ID나 진도는 다시 쓰지 않습니다.
- 제목을 입력하지 않았으면 원본 번호와 유형(예: 모의고사 23번 · 주제)을 기본 제목으로 사용합니다.

## 만드는 동안 전체 화면 복습
- 인식/생성/저장 중 화면 전체를 덮는 4지선다 복습 화면을 표시합니다. 뒤의 메뉴를 잘못 누르지 않도록 처리했고, 모바일 큰 버튼과 내부 스크롤·포커스 이동을 지원합니다.
- 최근 학습한 본문 최대 8개에서 저장된 단어와 기존 이해 문제를 사용하며 최대 40개를 오답률이 높은 순서로 정렬합니다. 새로운 문제를 만들려고 AI를 추가 호출하지 않습니다. 정확히 4개의 서로 다른 보기가 가능한 문제만 사용합니다.
- 문제별 기록이 있으면 그 문제의 실제 오답률을 사용합니다. 예전 이해 문제처럼 문제별 기록이 없으면 본문의 누적 퀴즈 오답률을 대신 쓰며 ‘이 본문 오답률’이라고 표시합니다. 기록이 없는 문제는 뒤로 정렬하고 오답률을 추정해 표시하지 않습니다.
- 앞으로 일반 퀴즈와 생성 중 복습 모두 문제 식별자를 학습 이벤트 metadata에 기록해 문제별 정렬이 가능하도록 했습니다. 복습 답안은 해당 원본 문서에 기록하며, 생성하려는 새 문서나 이전에 열었던 다른 문서에 섞지 않습니다. 별도의 XP나 완주 보상은 주지 않습니다.
- 답을 고르면 정답만 강조하고, 다음 문제를 눌러 이동합니다. 중복 클릭으로 다음 문제에 답이 입력되지 않도록 잠급니다. 키보드 1~4로 선택, Enter로 다음 문제를 지원합니다.
- 생성이 끝나면 현재 문제에 ‘이 문제가 마지막이에요!’를 표시합니다. 현재 문제의 답 확인 후 ‘다 되었어요 · 새 본문으로’로 이동합니다. 풀 문제가 없으면 완료 안내만 표시합니다.
- ‘건너뛰기’를 누르면 복습을 중단합니다. 생성 중이면 진행 안내를 유지하다 저장이 끝나는 즉시 새 본문으로 이동하고, 이미 완료되었으면 바로 이동합니다.
- 예전 학습 기록이 없으면 문제를 만들어내지 않고 생성 진행 안내를 표시합니다. 실패 시 입력을 유지한 채 본문 추가 화면으로 돌아가 다시 시도할 수 있습니다.

## 적용 방법
1. ZIP을 풀고 MoonWords 저장소 루트에 src, supabase, tests와 README 파일들을 합쳐 넣습니다. 같은 파일만 덮어쓰고 기존 폴더를 통째로 삭제하지 마세요.
2. GitHub Desktop에서 Commit → Push 후 Pages 배포가 완료되면 새로고침합니다.
3. **이번에는 Supabase의 process-document 함수를 반드시 재배포합니다. printmaker-ai가 아닙니다.** Dashboard → Edge Functions → process-document → Code에서 동봉된 supabase/functions/process-document/index.ts 전체 코드로 교체하고 Deploy 합니다. CLI를 쓰면 저장소 루트에서 `supabase functions deploy process-document`를 실행합니다.
4. 기존 Supabase 키와 Gemini 모델/키 설정은 그대로 사용합니다. 추가 SQL이나 패키지 설치는 없습니다. 사진도 분석 입력으로 들어가므로 기존 Gemini 요청 한도와 과금 기준이 적용됩니다.

## 검증과 범위
- 한국어·영어가 섞인 테스트 이미지로 실제 Tesseract 인식과 자동 생성 요청을 확인했습니다. 사진과 텍스트가 같은 분석 요청에 전달되는지, 원본 보기 5개와 OCR 텍스트가 저장되는지 확인했습니다.
- 모의고사 한 구간, 원본 문제 표시, 오답률 정렬, 문제별/본문별 기준 구분, 중복 답안 방지, 완료 직전 안내, 건너뛰기, 360/390/768px 전체 화면을 브라우저에서 확인했습니다.
- 분석 함수는 테스트용 모델 응답으로 사진 전달, 원문 보존 지침, 잘못된 이미지 거부, 일반 텍스트 요청 호환성을 검증했습니다. 운영 Gemini/Supabase를 호출하거나 실제 휴대폰 카메라 하드웨어를 실행하지 않았습니다.
- 사진의 모든 글자를 100% 정확히 읽는 것을 보장할 수는 없습니다. 흐리거나 잘린 부분은 복원하지 않고 판독 불가로 표시하도록 요청합니다. 중요한 문제는 생성 후 원본 문제·보기를 확인해 주세요.
- 저장소 기존 전체 TypeScript 검사에는 mammoth 브라우저 타입 및 백업/Cloudflare/Deno 환경 관련 오류가 있습니다. 이번 수정 소스의 새 타입 오류는 확인되지 않았습니다. Pages 빌드와 관련 테스트는 통과했습니다.
- 이 ZIP은 수정 코드입니다. GitHub Push와 운영 배포는 사용자가 진행합니다.
