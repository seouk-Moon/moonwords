# MoonWords 폴더 선택 · 달 반응 · 통합단어장 선택 추가

기준: GitHub main 26e7bae (이전 수업 맞춤 문제 업데이트 포함).

## 이번 변경
- 상단 왼쪽의 화살표 뒤로가기 버튼을 제거했습니다. 브라우저 자체 뒤로가기 기록은 유지됩니다.
- 홈의 달을 연달아 눌러도 매번 애니메이션이 다시 시작되고 인사말이 바뀝니다. 기기의 모션 줄이기 설정은 존중합니다.
- 처음 보관함을 열면 폴더를 먼저 고릅니다. 폴더를 고르기 전에는 본문/통합단어장 목록을 표시하지 않습니다. 미분류/전체 보기도 선택할 수 있습니다. ‘폴더 다시 고르기’로 목록에 돌아갑니다.
- 통합단어장 상단에 ‘추가된 단어 확인하기’를 넣었습니다. 연결된 원본 본문에 통합단어장 생성 후 새로 저장한 단어를 확인하고 선택한 것만 추가합니다.
- 별표 여부와 관계없이 새로 저장한 단어를 확인할 수 있습니다. 같은 단어·뜻이 이미 통합단어장에 있으면 제외하고, 뜻이 다른 항목은 별도 후보가 됩니다.
- 후보가 많으면 최대 500개씩 확인합니다. 선택하지 않은 항목은 다음에도 남아 있습니다. 단어장 최대 5,000개 제한은 유지합니다.
- 가져오는 단어의 예문·번역·출처·메모와 원본 별표/더 중요 표시를 함께 복사합니다. 기존 단어의 원본 별표 이어받기도 유지합니다. 새 단어를 자동 추가하는 이전 SQL 트리거는 중지합니다.
- 기존에 들어가 있는 단어와 학습 기록은 삭제하지 않습니다. 통합단어장 생성 전부터 원본에 있던 미선택 단어는 이번 ‘새 단어’ 후보에 포함되지 않습니다.

## 내가 할 일 (1번부터)
1. ZIP을 내려받아 압축을 풉니다.
2. Supabase → SQL Editor → New query를 엽니다.
3. ZIP의 supabase/migrations/202610200001_collection_selected_updates.sql 내용을 전부 붙여넣고 Run 합니다. 기존 통합단어장 SQL이 설치된 프로젝트에서 한 번 실행합니다. 다시 실행해도 안전합니다.
4. ZIP의 파일들을 MoonWords 저장소에 폴더 구조대로 합치고 같은 이름 파일만 덮어씁니다. 다른 파일은 삭제하지 않습니다.
5. GitHub Desktop → Commit → Push origin 합니다.
6. GitHub Actions의 Pages 배포가 완료되면 사이트를 새로고침합니다.
7. 폴더 → 통합단어장 → ‘추가된 단어 확인하기’ → 원하는 단어 체크 → ‘선택한 N개 추가하기’를 누릅니다.

이번 업데이트는 Edge Function 재배포나 API 키 변경이 필요하지 않습니다.

## 검증
Pages 빌드 통과. 자동 테스트 11개 통과(실제 PostgreSQL 실행 환경에서 새 SQL 재실행/사용자 격리/선택 가져오기/중복/별표/기존 동기화 중지 포함). 브라우저 검사에서 초기 폴더 선택, 달 연속 클릭, 한 단어만 추가, 목록 갱신, 미선택 유지, 모바일 360/390/768px 레이아웃을 확인했습니다. 사용자의 실제 Supabase/GitHub 배포는 수행하지 않았습니다. 전체 TypeScript 검사에는 기존 mammoth 타입 선언 오류 등 저장소의 기존 오류가 있으며 이번에 수정한 src 코드에는 새로운 오류가 없었습니다.
